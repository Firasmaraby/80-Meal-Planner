# Eighty

A micronutrient-first meal plan app. Users pick a plan for their calorie band and cuisine, follow it, and watch every vitamin and mineral fill in. A nutrient counts as done at **80% of the RDA**, the framework's finish line.

Built with Expo (React Native) for iOS and Android, plus a web preview. Supabase is the backend, and the app works fully offline without it.

## Status

Working app on the real, curated food library: 3,000 everyday foods (bundled) plus about 15,400 extended foods (loaded on demand), from 9 cited national databases with Canada's CNF first, then USDA. The 3 meal plans are samples; real plans come in through the plan importer. See [docs/ROADMAP.md](docs/ROADMAP.md) for what's built, what needs a phone build to test, and what's next.

## Run it

```bash
npm install
npm test                 # engine, importer, sync tests
npx tsc --noEmit         # typecheck
npx expo start           # press i / a for simulators, w for web
```

Native modules (haptics, SVG) work in Expo Go. Store builds use EAS: `npx eas-cli@latest build --profile production`.

## Adding meal plans

There are two ways in. Both end in the same report: import errors, a framework report per plan (calories against the band, protein, sat fat, omega 6:3, glycemic load, fatty fish, nutrients under 80% per day) and a fix-list you can paste back to the AI.

**From an Excel template**

1. Open `templates/MealPlan_Template.xlsx`. Regenerate it after the food DB changes with `python3 templates/build_template.py`.
2. Fill in Plans, Meals and Ingredients. Reference foods by `food_id` from the Foods sheet, or by name (the importer fuzzy-matches names and flags anything uncertain). **Never type nutrition values.** They're computed from the cited food database.
3. In the app, go to You, then Plan admin, choose **Upload .xlsx** and pick the file.

**From an AI** (ChatGPT, Claude, …)

1. In Plan admin choose **Paste from AI**. Tap **Copy sample as AI text** to show the AI the exact format, and give it your brief.
2. The AI answers with three CSV blocks under `=== PLANS ===`, `=== MEALS ===` and `=== INGREDIENTS ===` (same columns as the template sheets; tags separated by `|`). Code fences, notes around the blocks, blank lines, `;` as separator and quoted fields are all fine.
3. Paste the answer and tap **Import**. Tap **Copy fix-list for the AI** (on a phone this opens the share sheet), paste it back to the AI, and repeat until the plans pass. Error rows refer to the CSV line within each block, the header being row 1.

Then **Publish** (Supabase) or **Save on this device** (demo mode). Only import errors block publishing. Framework warnings are listed and counted in the publish confirmation, but don't block.

**From the command line**

```bash
node scripts/check-plan.mjs path/to/plan.xlsx      # the Excel template
node scripts/check-plan.mjs path/to/ai-answer.txt  # the AI's pasted text
node scripts/check-plan.mjs path/to/plan.txt --json
```

It prints the import issues, a per-plan, per-day table and the fix-list. Exit code 0 means every plan passes, 1 means import errors, 2 means the plans import but need work. It needs no extra install: it loads the app's TypeScript through the Vite that ships with vitest (tsx and vite-node aren't installed).

## Backend

See `supabase/README.md`. Copy `.env.example` to `.env.local` and set `EXPO_PUBLIC_SUPABASE_URL` and `EXPO_PUBLIC_SUPABASE_ANON_KEY`. Without them the app runs in offline demo mode.

## Food database

The app's foods come from the unified foodpipe v1.0 database (release `food-db-v1`; unzip it into `pipeline/input/foodpipe-v1.0/`, which is git-ignored). `pipeline/consumer/` turns it into the app library:

- one food per cluster, Canadian Nutrient File first, then USDA, then the rest; every source that confirms a food stays in its citations;
- three tiers: **everyday** (3,000 foods people actually log, bundled, and the only foods the AI plan kit offers), **extended** (searchable, ranked below, loaded on demand), **hidden** (baby food, supplements, duplicates, records without energy or not per 100 g edible portion), each hidden food with its reason;
- clean English names, one base food (`head`) per group, so search shows "Apple, raw" first and groups the other apple foods under it.

```bash
python3 pipeline/consumer/build.py           # rebuild src/data/foods.*.json, the seed CSV and pipeline/out/CURATION_REPORT.md
python3 pipeline/consumer/spot_check.py 60 7 # 60 random foods against the raw source values (0 mismatches expected)
python3 pipeline/search_check.py --real      # 300 everyday searches, top-1 / top-3
python3 templates/build_template.py && python3 templates/build_sample.py && python3 templates/build_ai_kit.py
```

Curation is driven by config files in `pipeline/config/`: `everyday_heads.txt` (the everyday list), `head_aliases.json` (foods a database names differently), `preferred_forms.json` (cooked rice, skinless chicken, Atlantic salmon first). The older `pipeline/run.py` (raw multi-sheet workbooks) is kept for new sources.

*Nutrition targets: US/Canadian Dietary Reference Intakes (National Academies). Educational information, not medical advice.*
